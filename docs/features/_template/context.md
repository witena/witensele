## Problem

> What does this feature exist to do, in two or three sentences? Write it from the
> user's point of view, not the implementation's.

## Scope

> What is explicitly in scope for the current milestone.

## Out of scope

> What this feature deliberately does not do, and which feature or milestone owns
> it instead. This is the section that stops the boundary from drifting.

## Dependencies

> documents, e.g. `../providers/context.md`. Note anything that depends on this
> feature in return.
