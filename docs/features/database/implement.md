# database — Implementation

## Approach

Four layers, each with one job, all under `src/main/db/` and none of them
importing electron:

| File | Owns |
|---|---|
| `schema.ts` | The drizzle definition of the seven tables and the `…Row` types inferred from them |
| `migrations/*.sql` + `migrations/meta/` | Generated by drizzle-kit from `schema.ts`; the SQL that actually creates the file |
| `migrate.ts` | Applying those files: bundled via `import.meta.glob`, tracked in `__migrations`, one transaction per file |
| `database.ts` | `openDatabase(filePath)` — directories, pragmas, drizzle, migrations, `close()` |
| `repositories/*.ts` | Shared-type-in, shared-type-out persistence for each domain, plus `createRepositories(db, { encrypt })` |
| `../errors.ts` | `BackendFailure`, `notFound()`, `validation()` |
| `testing.ts` | Temporary-file fixtures for the tests; imported by no production module |

The seam is deliberate: `openDatabase` takes a **path**, `createRepositories`
takes a **handle**, and services take a `Repositories`. Only `src/main/index.ts`
knows that the path comes from `app.getPath('userData')`, which is what keeps the
whole layer liftable into a Node server (CLAUDE.md rule #5).

### Migrations that survive bundling

drizzle ships `migrate(db, { migrationsFolder })`, which reads `.sql` files from
disk at runtime. The main process is bundled into a single `out/main/index.js`
and the folder is not copied next to it, so that approach breaks the moment the
app is packaged. Instead:

```ts
const migrationSources = import.meta.glob('./migrations/*.sql', {
  query: '?raw',
  import: 'default',
  eager: true
}) as Record<string, string>
```

`import.meta.glob` is a Vite primitive, and both toolchains that run this code —
electron-vite for the main build, vitest for the tests — resolve it, so the tests
exercise the production code path rather than an approximation. The build is
verified by `grep "CREATE TABLE" out/main/index.js`.

`runMigrations(sqlite)` then:

1. creates `__migrations (name, applied_at)` if it does not exist;
2. sorts the globbed files by name (drizzle prefixes them `0000_`, `0001_`, …);
3. skips the ones already recorded;
4. splits each remaining file on `--> statement-breakpoint`, drizzle's own
   separator, and applies the statements plus the `__migrations` row **in one
   transaction**, so a failure halfway leaves the file unapplied rather than half
   applied.

To add a migration: edit `schema.ts`, run `npm run db:generate`, and commit the
new `migrations/*.sql` together with the updated `migrations/meta/`. Never edit a
migration that has already shipped — write a new one.

All three migrations after the initial schema are the same shape and it is the
shape to copy: **one nullable column, no default, no rewrite**
(`0001` added `messages.in_reply_to`, `0002` added `providers.auth` in S5.3,
`0003` added `chats.goal` in S5.10).
SQLite can add a nullable column in place, so an existing database is upgraded
in microseconds and a row written by an older build stays readable — `NULL` maps
through `optional()` to an absent field, and the shared type's documented
default (`providerAuth()` reads an absent `auth` as `apiKey`) supplies the
meaning. A `NOT NULL DEFAULT` would rewrite the table *and* put the default in
two places.

### Repositories

Every repository is a factory returning a plain object, so a service takes an
interface and a test takes a temporary file. They all follow the same rules:

- **Shared types only.** A caller never sees a row, a JSON string, a 0/1 boolean
  or the API key ciphertext.
- **`userId` on every method**, last parameter, defaulting to `LOCAL_USER_ID`
  (`setMembers` takes it first, since its other arguments are both required).
  Every query filters on it.
- **UUID ids** from `crypto.randomUUID()`, epoch-millisecond timestamps from
  `Date.now()`, both assigned here rather than by the database.
- **Missing row → `BackendFailure` with `code: 'not_found'`**, including when the
  row exists but belongs to another user.
- **Absent optional fields are absent**, not `undefined`: `NULL` maps through the
  `optional()` helper to a missing key, which is what `exactOptionalPropertyTypes`
  requires and what JSON transport preserves.
- **`''` clears** a nullable column in a patch; omitting the field keeps it.

## Data flow

Persisting one user message, as it will run from S1.7:

```
composer → messages store → BackendClient.invoke('chat.send', …)
  → main handler → repositories.messages.create({ chatId, senderType: 'user', … })
      → BEGIN
        max(seq) for this chat, +1
        INSERT INTO messages
        UPDATE chats SET updated_at   ← the chat floats to the top of the list
      → COMMIT
  → Message (shared type) → message.created event → renderer
```

A streaming agent reply is the same insert with `status: 'streaming'` and empty
`parts`, followed by repeated `messages.update(id, { parts })` as chunks arrive
and a final update carrying `status`, `usage` and `mentions`. `inReplyTo` is
written **once, at insert**, and never patched: who asked for a reply is decided
before it is written, while what it mentions is only known when it ends.

Reading a chat, two different orders for two different consumers:

```
chat view (newest first, paged)   → messages.list({ chatId, before, limit })
model context (oldest first, all) → messages.listForContext(chatId)
```

Startup:

```
app.whenReady → join(app.getPath('userData'), 'witena.db')
  → openDatabase(path)   mkdir → better-sqlite3 → pragmas → drizzle → runMigrations
  → module-level handle; console.log of the path
app.before-quit → handle.close()   (checkpoints WAL)
```

The error path: a repository throws `BackendFailure`, which already satisfies
`BackendError`; S1.3's handler registry calls `toBackendError()` and the plain
object crosses the boundary, because an `Error` subclass does not survive
structured clone with its prototype intact.

## Key types and contracts

This feature adds no `BackendClient` method and emits no event — it is the layer
those methods are implemented on top of. The contracts it does add are the
repository interfaces:

| Repository | Methods |
|---|---|
| `providers` | `list`, `get`, `create`, `update`, `delete`, `getApiKeyCiphertext` |
| `agents` | `list`, `get`, `create`, `update`, `delete` |
| `mcpServers` | `list`, `get`, `create`, `update`, `delete` |
| `chats` | `list`, `get`, `create`, `update`, `delete`, `setMembers`, `listMembers` |
| `messages` | `create`, `update`, `get`, `list`, `listForContext`, `nextSeq` |
| `settings` | `get`, `update` |

Types worth naming:

| Type | Where | Meaning |
|---|---|---|
| `DrizzleDb` | `database.ts` | `BetterSQLite3Database<typeof schema>`, what every repository takes |
| `DatabaseHandle` | `database.ts` | `{ db, sqlite, close() }` |
| `Repositories` | `repositories/index.ts` | All six, the object services receive by injection |
| `RepositoryOptions` | `repositories/index.ts` | `{ encrypt }` — the only crypto this layer knows about |
| `MessageCreateInput` | `repositories/messages.ts` | `Omit<Message, keyof EntityBase>`; `seq` is assigned, not supplied |
| `MessagePatch` | `repositories/messages.ts` | `parts`, `status`, `usage`, `mentions`, `error` |
| `BackendFailure` | `src/main/errors.ts` | `Error` that also implements `BackendError`, with `toBackendError()` |

Patch semantics, identical in every repository:

| In the patch | Effect |
|---|---|
| field absent | the stored value is kept |
| `''` on a nullable **string** column (`apiKey`, `baseUrl`, `presetId`, `command`, `url`, `error`) | the column is set to `NULL` |
| any other value | the column is replaced |
| a nullable **union** column (`providers.auth`, S5.3) | absent keeps it; there is no `''` spelling, because `''` is not a member of the union — the way back is the other value (`auth: 'apiKey'`) |
| `settings.update` | shallow merge, with `timeouts` merged field by field |
| `chats.update({ settings })` | merged over the stored settings, so a partial object is safe |
| `chats.update({ goal })` | **replaced**, not merged (S5.10). `null` removes the goal; there is no `''` spelling, because `''` is not a `ChatGoal`. The one patch field in the layer that is deliberately not a merge — see `context.md` |

Each test file opens its own database in a fresh `fs.mkdtempSync` directory under
`os.tmpdir()` and removes it afterwards — a real file rather than `':memory:'`,
because half the point is that a close and reopen behaves correctly.

## Known limitations and TODOs

- **No zod validation.** The repositories check existence, ownership and duplicate
  members; everything else is trusted. The S1.3 handlers validate their payloads.
- **`nextSeq` is `max(seq) + 1`** inside the insert transaction. Correct for one
  process and one SQLite writer; a multi-writer server version needs a real
  sequence.
- **No cross-repository referential integrity beyond the two cascades.**
  `agents.providerId` and `agents.mcpServerIds` are plain strings, so deleting a
  provider leaves agents pointing at a missing one. S1.6 decides whether that
  becomes a foreign key or a UI warning.
- **`chat_members` has no `userId`** — it is a pure join table, scoped through the
  chat and the agents, both of which are checked before a write.
- **`DEFAULT_CHAT_TITLE` is English**, stored rather than translated; see the open
  question in `context.md`.
- **No backup, export or vacuum** and no `PRAGMA optimize` on close. S4.4.
